# ADAS 叠加/检测偏移修复记录（2026-11-01）

## 1. 现象

开启自动驾驶辅助（空格 + `6`）后：

- 画面里的车道三格条、方向箭头、十字准星与视频画面**对不齐**；
- 车辆/行人检测框整体**横向偏移约 256 px**；
- 车道线看起来是"歪"的，`几何校验失败 上宽/下宽/左/右` 等提示频繁出现。

## 2. 根因

本板 HDMI 采集链路输出的线性帧起点比真实画面**整体右移 256 px**（行内回卷、跨行连续）。
ADAS 增量补丁原本只在**显示端**做了 256 px 回卷（`m_adasRollPx = 256`），于是：

- 显示到屏幕上的画面是纠正过的；
- 但推理链路读到的仍是**未纠正**的原始帧，检测框/车道线按原始坐标绘制 → 固定偏移 256 px。

用自制测试图（1280×720，红色竖线在 x=640、横线在 y=360）量化确认：

| 状态 | 竖线实测位置 | 说明 |
| --- | --- | --- |
| 显示端回卷关闭（M 键，`roll_px=0`） | x = **896** | 原始帧，整体右移 256 px |
| 显示端回卷开启（`roll_px=256`） | x = **640** | 显示纠正正确 |

垂直方向仅有 +3 行偏差（可忽略）。

## 3. 修复方案（已上线）

把 256 px 行内回卷**搬到"提交到共享 FrameBuffer 之前"**，让显示链路与推理链路看到同一张已纠正的帧：

- `frame_capture.cpp` 新增 `adasRotateRgb565RowsLeft()`，在 HDMI 快通道（`copy_mode=5` 的 RGA/宽拷贝路径）`commitFrame` 之前执行；
  同时保留快照/非 mmap 路径的同一处理（共 3 处插入）。
- 回卷像素数可用环境变量 `HDMI_ROLL_PX` 覆盖，默认 256；设为 0 即关闭。
- 显示端默认回卷改为 **0**（`mainwindow.h:179 int m_adasRollPx = 0;`），`M` 键保留为应急开关（现场若发现画面仍偏移，按一次 `M` 即可恢复显示端回卷）。

补丁实现位置：`src_adas/adas_patch.py`（`FC_HELPER_*` / `FC_CALL_*` / `FC_FAST_*` 三组锚点 + `force_display_roll_zero()`）。

## 4. 验证结果

| 项目 | 结果 |
| --- | --- |
| 测试图竖线位置（不按 M） | x = **640**（与画面中心一致） |
| ADAS 叠加十字准星 | 与测试图中心 (640, 360) 对齐 |
| 标准一键脚本 | `=== PASS (STANDARD ADAS@60Hz): input=61fps ===` |
| 采集读数 | `input=61 source=HDMI processed=61 slot_skips=0 copy_mode=5` |
| 单帧处理 | `proc_avg_us` 约 4.1 ms（修复前 2.6 ms，多出的约 1.5 ms 为逐行回卷开销），仍稳定 61 fps |
| 显示帧率（ADAS 关） | 55–56 FPS |

## 6. 板端重编步骤（含踩坑）

```sh
# 0) 先把 PC 侧修好的补丁上传（注意：必须加 MSYS_NO_PATHCONV=1）
python run/rk.py --put src_adas/adas_patch.py /userdata/hs_tools/adas_pkg/adas_patch.py

# 1) 时钟必须正确，否则 qmake 段错误 / make 认为对象比源码新而不重编
date                                            # 板端应接近当前时间（UTC）
# 如偏差大：date -s '2026-11-01 09:20:00'（UTC）

# 2) 用"干净"的 frame_capture.cpp 重打补丁（该文件没有 .adas_bak，重复打会 skip）
python3 adas_patch.py .                          # 期望 frame_capture.cpp (+3 处)

# 3) 清掉可能残留的坏对象后再编（曾出现 g++ ICE 留下 656 B 的 .o）
rm -f frame_capture.o adas_overlay.o main.o mainwindow.o moc_mainwindow.o
make -j1                                        # 内存紧张时不要 -j4

# 4) 自检：二进制里应能找到 HDMI_ROLL_PX
md5sum camera_capture_v2; strings camera_capture_v2 | grep -c HDMI_ROLL_PX   # 期望 1
```

注意：

- `frame_capture.o` 的时间戳若比源码新（历史构建遗留），`make` 会跳过重编，导致"改了没生效"——务必删除该 `.o`。
- 重编后必须重跑 `run\RUN_STANDARD.ps1 -Shot` 确认 `PASS`，并抓一张 `kmsgrab` 图核对画面。

## 7. 现场使用建议

- 正常演示无需按 `M`；`M` 只作应急（画面整体横向偏移时按一次，再按一次可切回）。
- `HDMI_ROLL_PX=0` 可整体关闭采集端回卷（用于接其它信号源时对比）。
- 若更换笔记本/显示器导致 HDMI 时序变化，先重跑一键脚本，用测试图核对一行位置，再调 `HDMI_ROLL_PX`。
